# Zenda — Product Backlog, HU y criterios de validación

Documento técnico para que el agente Codex valide la implementación de la aplicación móvil contra el Product Backlog y los criterios de aceptación.

## Resumen de cobertura

- Total de historias de usuario en Product Backlog: **49**
- Total de historias con criterios de aceptación: **49**
- Total de escenarios de aceptación: **98**
- Cada HU contiene 2 escenarios de aceptación.

## Instrucciones de uso para Codex

1. Validar cada HU contra el código fuente de la app móvil, servicios, almacenamiento local/remoto y navegación real.
2. Para cada HU, crear o ejecutar pruebas unitarias, widget tests, integración o pruebas manuales asistidas según corresponda.
3. No marcar como cumplida una HU si solo existe la pantalla, pero no existe persistencia, validación, cálculo, navegación o estado esperado.
4. Cuando una HU tenga escenarios de error o datos insuficientes, validar explícitamente que no se creen datos incorrectos y que el mensaje sea entendible para el usuario.
5. Al finalizar, generar un reporte indicando: HU, estado observado, evidencia, archivo/pantalla validada, errores encontrados y recomendación de corrección.

- **Cumple:** los escenarios positivos y negativos funcionan, los datos persisten y la UI refleja el estado correcto.

- **No cumple:** la funcionalidad no existe, falla el flujo principal o contradice el resultado esperado del criterio de aceptación.
